# Notebook-Todolist · 笔记课间

一个面向学生的轻量 Web 应用，把课堂笔记、作业待办和间隔复习连在一起，支持自行部署。

**笔记、待办、复习卡是同一份内容的不同视图。**

在笔记中写下 `- [ ] 完成课后练习`，就得到关联原文的待办；用 `==重点==` 标记知识点，就得到可以复习的挖空卡。日常从「今日」页进入，先处理到期作业，再复习该记住的内容。

## 功能

| 功能 | 当前支持 |
| --- | --- |
| 课程与课表 | 设置每周课程时间；普通新建笔记按当前上课时间归类，也能手动修改 |
| Markdown 笔记 | 编辑、预览、课程筛选、全文搜索，以及 LaTeX 公式渲染 |
| 笔记待办 | 自动提取 Markdown 复选框，关联来源笔记；默认截止于所属课程下一节课，可手动修改 |
| 复习卡 | `==重点==` 自动生成挖空题；点击「记住了 / 没记住」，按 1 / 3 / 7 / 15 天安排复习，遗忘后重新开始 |
| 今日页 | 集中显示今天到期和已逾期的待办、复习卡，以及课程考试倒计时 |
| 随手记与草稿 | 登录后一键进入空白编辑页；无需先选课程，未归类内容单独浏览；编辑内容自动暂存到当前浏览器 |
| 分享长图 | 「纸张」「夜读」两套模板，预览并下载笔记长图 |
| 手机与 PWA | 适配手机和电脑、深色模式、主屏幕安装、应用外壳缓存与离线提示 |
| 用户账号 | 用户名密码注册登录、密码哈希、数据按用户隔离、CSRF 防护及登录失败限速 |
| AI 助手 | 整理笔记、识别自然语言任务、生成问答卡、识别板书照片；生成结果确认后再保存 |
| 板书与附件 | 浏览器先压缩识别图片，公式输出 LaTeX、作业输出复选框；原图可作为笔记附件保留 |
| 考试冲刺与面板 | 设置考试日期、压缩复习间隔；查看课程复习正确率、待办完成率和近 84 天学习热力图 |

## 本地运行

Windows 可完整下载并解压项目后，双击 `start-windows.cmd`。入口会准备 Python 3.12 与独立依赖环境，使用 Waitress 启动并打开浏览器；数据默认保存在 `%LOCALAPPDATA%\Notebook-Todolist`。完整说明见 [LOCAL.md](LOCAL.md)。Windows CMD 入口已在本机完成实际启动与浏览器验收，范围与限制见 [WINDOWS-ACCEPTANCE.md](WINDOWS-ACCEPTANCE.md)；下列命令也可用于手动运行。

需要 Python 3.12。前端资源已随仓库提供，无需 Node.js 构建。

```bash
git clone https://github.com/systemxthzeonxlu25-spec/Notebook-Todolist.git
cd Notebook-Todolist
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
cp -n .env.example .env
python app.py
```

默认使用本机 `127.0.0.1:5000`，在浏览器输入该地址并注册账号即可开始使用。Windows 可使用 `py -3.12 -m venv .venv` 创建环境，之后通过 `.venv\Scripts\python.exe` 执行安装和启动命令，并手动复制 `.env.example` 为 `.env`。

`requirements-dev.txt` 包含应用依赖和 pytest；只运行应用时也可以安装 `requirements.txt`。首次启动自动初始化 SQLite。数据库与原图默认位于被 Git 忽略的 `instance/` 目录，升级时需要保留这些文件。

本地 `SECRET_KEY` 留空时会在每次启动时生成临时值，重启后需要重新登录。生产部署必须提供至少 32 个字符的稳定随机密钥；具体生成方式见 [DEPLOY.md](DEPLOY.md)。不要覆盖已有 `.env`，也不要把真实配置、数据库、上传文件或 API Key 提交到 Git。

### 常用配置

配置从环境变量读取；本地可使用 `.env`。下面的默认值与 [.env.example](.env.example) 对应：

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `APP_ENV` | `development` | 生产设为 `production`，此时必须配置 `SECRET_KEY` |
| `SECRET_KEY` | 留空 | Flask 会话签名密钥；生产使用至少 32 个字符的随机密钥并保持稳定 |
| `DATABASE_PATH` | `instance/notebook.sqlite3` | SQLite 路径；相对路径以项目根目录为基准，也支持绝对路径 |
| `UPLOAD_FOLDER` | `instance/uploads` | 私有原图目录；生产放在代码目录之外 |
| `TZ` | `Asia/Shanghai` | 课表、自然语言日期、考试日和学习统计使用的时区 |
| `HOST` | `127.0.0.1` | `python app.py` 的监听地址；生产 Gunicorn 使用独立配置 |
| `PORT` | `5000` | 本地运行端口；生产内部端口为 `18765` |
| `SESSION_COOKIE_SECURE` | `false` | 本地 HTTP 用 `false`，生产 HTTPS 用 `true` |
| `TRUST_PROXY` | `false` | 部署在本机 Caddy 后设为 `true`；仅对原始回环连接信任一层代理，取得真实客户端 IP 与协议 |
| `REGISTER_ENABLED` | `true` | 默认允许任何人注册；设为 `false` 可关闭新注册，不影响已有账号登录 |
| `MAX_CONTENT_LENGTH` | `16777216` | HTTP 请求体上限，默认 16 MiB；具体文本、图片接口另有更小限制 |
| `AI_ALLOWED_HOSTS` | `api.deepseek.com,api.openai.com` | 管理员允许的 AI 服务域名，逗号分隔；不填写密钥或 URL 路径 |

关闭公开注册后，可在应用相同的配置环境中使用命令创建账号，密码通过隐藏提示输入：

```bash
python -m flask --app app create-user
```

这个命令只创建新账号，不能找回旧账号的密码或认领其数据。

## 使用方式

1. 在「课表」里创建课程、设置每周上课时间。
2. 从「笔记」新建课堂笔记，或从「随手记」直接开始输入；随手记默认不归类。
3. 在正文中标记作业与重点，保存后查看待办和复习卡。
4. 每天打开「今日」，勾选已完成作业，查看卡片答案并反馈记忆情况。
5. 考试临近时为课程设置考试日期，在数据面板查看学习活动。

例如：

```markdown
# 高数 · 导数

导数描述==函数的瞬时变化率==。

- [ ] 完成教材第 32 页练习
```

保存这篇笔记会生成一张挖空卡和一个待办。Markdown 中的任务默认使用下一节课作为截止时间；像「下周三前交报告」这样的自然语言日期，需要使用 AI 任务识别并确认结果，或手动设置。

没有课表或笔记未归类时，待办可以没有默认截止日期。草稿只是浏览器内的暂存，点击「保存笔记」才会提交到服务器。

### 考试冲刺与统计口径

考试日期以应用时区的**当天 00:00** 为复习安排截止点。设置未来考试日会提前卡片到期时间；后续复习间隔按剩余时间压缩，并不超过正常间隔。系统为按时复习的用户安排至少两轮机会，实际完成仍需用户主动操作；临近考试时，间隔可能很短。

考试当天及过去日期不再压缩后续复习间隔，已经逾期的卡片仍会显示；取消考试也不会把此前提前的卡片自动推迟。

- **复习正确率**：该课程「记住了」的次数 ÷ 已记录的复习回答次数，表示回答结果，不代表知识掌握率。
- **待办完成率**：当前已完成待办数 ÷ 当前仍存在的待办总数；没有待办时不显示百分比。
- **学习热力图**：按应用时区展示近 84 天的活动次数；创建笔记、每次回答复习卡、每个待办首次完成各记一次。反复取消再勾选同一待办不会重复累计，编辑笔记也不重复计为新建。

删除笔记或卡片可能联动删除对应复习记录，因此课程正确率会随之变化；热力图保留已经发生的活动计数。

## AI 配置与使用

登录后打开「设置」，在页面中填写 Base URL、API Key 和模型名。默认示例为：

| 设置项 | 示例 |
| --- | --- |
| Base URL | `https://api.deepseek.com` |
| 模型名 | `deepseek-v4.1-flash` |
| API Key | 在自己的浏览器设置页填写，不写入代码或服务器配置 |

这个模型名是可修改的示例，供应商是否提供该模型、账号是否具备权限以及是否支持图片输入，需要以供应商实际服务为准。未配置 AI 时相关按钮禁用，并提示前往设置；基础笔记、待办和复习不依赖 AI。

API Key **只保存在当前浏览器、当前账号的 localStorage 中**。使用 AI 时，通过 `X-AI-Key` 请求头临时传给后端，再由 OpenAI Python SDK 转发；不写入后端数据库、环境文件、会话或日志。换设备需要重新配置，也可以在设置页清除已保存的信息。不要在聊天、issue、截图或提交记录中提供真实密钥。

自定义服务需由部署管理员加入 `AI_ALLOWED_HOSTS`，只支持公网域名、HTTPS 和 443 端口，并验证证书。后端校验域名解析、固定已验证的公网 IP 连接且保留原域名 TLS 验证，不跟随重定向。内网地址、IP 字面地址、HTTP 服务和代理环境变量不受支持；普通用户不能修改管理员白名单。

整理笔记后可以替换原文，或保留原文并追加整理版；任务和问答卡需确认后才加入待办或复习。AI 可能误读、遗漏或推算错日期，请在保存前核对结果。

照片识别会在浏览器用 canvas 压缩为长边约 2000 像素的 JPEG，再按 OpenAI 多模态格式发送。结果以 Markdown 呈现，公式使用 LaTeX/KaTeX，作业要求使用 `- [ ]`。原图附件在笔记保存后上传；请确认上传完成后再关闭或刷新页面。

## PWA 与离线行为

支持 manifest、service worker 和添加到手机主屏幕。生产环境需要 HTTPS；iOS 通常通过 Safari 的「分享 → 添加到主屏幕」手动安装，安装入口和显示模式因浏览器而异。

service worker 只缓存公开的应用外壳资源，不缓存登录后的 HTML、API 数据或私有附件。已打开的编辑页可以继续把文字草稿保存在 localStorage；断网后重新导航会显示离线提示。完整离线编辑、离线数据浏览和联网后的自动同步尚未实现。

## VPS 部署

完整步骤见 [DEPLOY.md](DEPLOY.md)，部署文件位于 [deploy/](deploy/)。当前提供的是配置文件和待执行清单，尚未在用户 VPS 上执行部署。

面向 1–2 核、小内存机器，使用单 Gunicorn worker、两个线程，后台仅监听 `127.0.0.1:18765`；通过独立 Caddy 服务提供 HTTPS，systemd 负责开机启动和异常重启。SQLite 每日使用在线备份 API 创建一致快照，默认保留 14 天；原图与环境文件需要另外备份。

部署清单的第一步是检查并备份现有代理和防火墙配置，随后检查资源、已有服务、DNS 和端口。不会改动、停止或重启已有代理，也不会自动修改任何防火墙规则。80/443 被占用或发现已有 Caddy 时必须停止继续安装，先确认新的部署方案；需要开放的端口在清单中单列，由 VPS 所有者确认后手动处理。回滚只涉及本项目新增的服务。

## 技术栈与项目结构

- 后端：Python 3.12、Flask、SQLite、OpenAI Python SDK、Pillow。
- 前端：原生 HTML / CSS / JavaScript，Jinja 模板，无前端构建工具要求。
- 浏览器组件：marked、DOMPurify、KaTeX、html2canvas，发行文件和许可证保存在 `static/vendor/`，运行时无需从 CDN 下载。
- 部署与验证：Waitress（本机）、Gunicorn / Caddy / systemd（VPS）、pytest。

```text
app.py                  应用工厂、页面和业务 API
auth.py                 注册登录、会话与访问控制
proxy.py                本机反向代理信任边界
db.py                   业务数据库访问、数据隔离与事务
domain.py               课表、笔记提取、复习和统计规则
ai.py                   无持久化的 AI 请求转发与输入输出校验
uploads.py              私有原图附件访问与文件管理
templates/              页面 DOM 与语义化 class 命名
static/tokens.css       应用颜色、字号、间距等统一设计变量
static/*.css            页面与组件样式
static/*.js             页面逻辑、状态、事件和 API 调用
static/vendor/          第三方浏览器组件及许可证
tests/                  自动化测试
scripts/                本机依赖准备与独立数据启动器
start-windows.cmd       Windows 双击启动入口
LOCAL.md                本机安装、数据位置和故障处理
deploy/                 Gunicorn、Caddy、systemd 和备份配置
.env.example            不含真实密钥的配置示例
DEPLOY.md               VPS 逐步部署、备份恢复和回滚清单
```

业务数据库操作集中在 `db.py`，路由和业务规则不直接写 SQL；部署备份脚本独立使用 SQLite 在线备份 API。

为后续重新设计前端，页面结构保留在 `templates/`，应用模板不写内联样式；JS 负责逻辑和 API 调用，通过 class 表达界面状态，不拼接样式。应用视觉变量集中在 `static/tokens.css`，换肤从这里和页面 CSS 开始；`static/vendor/` 中的第三方发行 CSS 保持原样。

## 自测

安装开发依赖后，在项目根目录执行：

```bash
python -m pytest -q
```

此前 Linux 环境 154 项自动化测试通过；2026-10-12 的 Windows 实机运行结果为 **150 项通过、1 个 POSIX 专用备份测试模块跳过**，包含新增的真实 HTTP 附件、会话与备份恢复回归测试。测试覆盖核心笔记流程、账号隔离、CSRF、登录限速、AI 模拟接口与输入边界、附件权限、复习冲刺和统计规则，以及生产代理、异常输入、SQLite 备份恢复和本机启动器。AI 测试使用假密钥与模拟上游，不会消耗真实服务额度。也已进行真实浏览器交互检查；其中 AI 响应使用模拟数据，不能代替真实供应商验证。

本地已实际启动 Gunicorn 验证注册和保存流程，使用 Caddy 2.11.7 官方二进制校验反向代理配置，并检查 systemd 单元语法；尚未在真实 VPS 启动这些服务或申请证书。

本机启动器已在 Linux 上完成全新依赖安装、中文与空格路径启动、离线复用依赖，以及重启后原浏览器会话和数据保留检查。真实 Waitress 服务上的桌面与 320px 手机浏览器验收通过，包含附件上传、两套分享长图、草稿恢复、统计和离线外壳；在线页面 JavaScript 错误为 0。2026-10-12 又完成 Windows x64 实机启动、Edge 浏览器功能验收、重启持久化及独立目录的备份恢复检查，具体范围见 [WINDOWS-ACCEPTANCE.md](WINDOWS-ACCEPTANCE.md)。

## Known Issues

- Windows CMD 入口已实际运行；本次使用项目内独立 Python 3.12、已核验的 PyPI 安装包及自定义数据目录。自动 winget 安装、默认数据目录写入和开机自启未在这次验收中验证，详情见 [WINDOWS-ACCEPTANCE.md](WINDOWS-ACCEPTANCE.md)。
- 尚未使用真实 API Key 验证供应商模型可用性、出题质量和板书识别效果；默认模型名仅为可修改示例，也不保证具备视觉能力。
- VPS 部署文件已经准备，真实机器的资源、域名、证书、端口占用与现有代理兼容性尚未验证。
- 暂无邮箱绑定和找回密码流程；`create-user` 只能创建新账号，不能恢复旧账号或其数据。
- 开发早期无登录版本的 `local` 数据不会自动归属新注册用户，避免错误认领；迁移需另行确认归属。
- 本地草稿不跨设备同步；清理浏览器存储会清除草稿和本机 AI 配置。完整离线编辑与同步仍在 Roadmap。
- 待办勾选暂不反向修改原笔记中的 Markdown 复选框。
- 未上传的原图只保留在当前页面，刷新或关闭页面会丢失待上传队列；文字草稿不包含这些原图。
- 分享长图单篇高度上限为 12000 CSS 像素，过长笔记需要拆分；导出包含标题、课程和正文，不包含独立附件列表。
- PWA 安装方式和独立窗口表现因浏览器而异；手机通常需要 HTTPS，iOS 需手动添加到主屏幕。
- 删除卡片或原文会改变课程复习统计的分母；热力图保留历史活动次数，两者采用不同统计口径。
